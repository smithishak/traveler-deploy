# traveler-deploy

Личный VPN на Ubuntu 22.04/24.04: **wg-easy v15 + AmneziaWG**, панель по HTTPS через Caddy. Нужны root, KVM/VPS с собственным ядром и публичный IPv4. Контейнерный VPS без возможности загрузить kernel-модуль не подходит.

## Установка

На чистом сервере:

```bash
apt-get update && apt-get install -y git python3
git clone https://github.com/smithishak/traveler-deploy.git
cd traveler-deploy
bash deploy.sh
```

Установщик ставит Docker и DKMS-модуль AmneziaWG, создаёт администратора и запускает панель. Откройте `https://<SERVER_IP>` и примите самоподписанный сертификат. Логин и пароль находятся в `.env` (`INIT_USERNAME`, `INIT_PASSWORD`); в журнал они не выводятся.

Клиентские конфиги/QR создаются в панели. Нужен совместимый с AmneziaWG клиент; обычный WireGuard не поддерживает параметры обфускации.

Опциональные параметры **первой установки**:

```bash
SERVER_IP=1.2.3.4 WG_ADMIN_USERNAME=admin WG_PORT=443 WG_MTU=1280 bash deploy.sh install
```

`WG_ADMIN_PASSWORD` можно задать заранее; иначе создаётся случайный пароль. `WG_DNS` по умолчанию `1.1.1.1,8.8.8.8`. Допустимый MTU 1280–1420. Основной UDP-порт не может совпадать с резервными 53/4500. Значения с одинарной кавычкой, обратным слешем и переводами строк отклоняются.

## Безопасный повторный запуск

```bash
bash deploy.sh install
# или просто
bash deploy.sh
```

При существующем `.env` команда использует сохранённые настройки, не генерирует новый пароль, не меняет клиентов, MTU или SQL-хуки и не скачивает новые образы. Случайные переменные окружения не перекрывают `.env`. Если том VPN содержит данные, а `.env` потерян, новая инициализация запрещается: сначала восстановите настройки.

Первичная установка задаёт MTU новых клиентов и MSS для IPv4/IPv6 через SQLite wg-easy. Повторный запуск и обновление не правят пользовательские настройки базы. MTU самого серверного интерфейса может отличаться от MTU клиентских конфигов.

## Диагностика

```bash
bash deploy.sh doctor
```

Проверяет Docker/Compose, модуль AmneziaWG, образы и состояние контейнеров, интерфейс `wg0`, совпадение его порта с настройками, публикации трёх UDP-портов, IPv4 forwarding, NAT IPv4/IPv6, локальную HTTPS-страницу входа, целостность SQLite, MTU/MSS, DNS из контейнера. Показывает число клиентов и недавних handshake без IP клиентов, ключей и паролей. Код выхода: `0` — проверки прошли, `1` — найдена проблема.

Успешный doctor **не подтверждает** доступность UDP из чужой сети, выход в интернет через VPN или обход DPI. Это проверяется подключением внешнего клиента. DNS-тест подтверждает DNS контейнера, а не DNS внутри клиентского туннеля. Сертификат проверяется с разрешённым самоподписанным TLS.

## Обновление с автоматическим откатом

```bash
bash deploy.sh update
# конкретная совместимая версия:
bash deploy.sh update --wg-image ghcr.io/wg-easy/wg-easy:15.5.0
# отдельная версия Caddy:
bash deploy.sh update --caddy-image caddy:2-alpine
```

Обновляются Docker-образы; исходники из GitHub эта команда не загружает. По умолчанию используются ссылки на образы из `docker-compose.yml`. Выбор другого образа — ответственность администратора; автоматический переход на новую major-версию wg-easy не предусмотрен.

Порядок работы:

1. Проверяется работоспособность текущей установки и загружаются новые образы.
2. Сохраняются `.env`, Compose, Caddyfile, настройки резервного TCP (если включён), текущие образы и **все именованные тома активных сервисов**, включая базу/ключи VPN и сертификаты Caddy. Для согласованной копии сервисы ненадолго останавливаются.
3. Контейнеры пересоздаются на скачанных образах. Точные образы сохраняются локальными тегами в `.traveler/images.json`, без повторной загрузки при следующем запуске.
4. Проверяются интерфейс, порты, NAT, forwarding, HTTPS (три успешных прохода подряд), затем полный `doctor`.
5. При неудаче восстанавливаются прежние образы, файлы и тома; повторно проверяется запуск. Команда возвращает `1`, даже если откат успешен: обновление не состоялось.

VPN ненадолго прерывается. Изменения, сделанные после момента бэкапа, при откате теряются; во время обновления не редактируйте клиентов. Обновление модулей ядра/ОС не входит в транзакцию. Проверка запуска не гарантирует совместимость экспортированных профилей с каждым клиентским приложением.

Если процесс убит или сервер перезагрузился посреди транзакции, следующий запуск обнаружит `.traveler/pending.json` и попросит восстановление:

```bash
bash deploy.sh rollback
```

Если сам откат не удался, маркер остаётся для повторного восстановления. Для изменения времени ожидания новой версии: `--timeout 120` (10–600 секунд). При сбое скачивания рабочие контейнеры не заменяются.

**Управляйте запуском через `deploy.sh`**: обычный `docker compose up` не учитывает `.traveler/images.json` и резервный транспорт из `.traveler/tcp-compose.json`.

## Бэкап и ручной откат

```bash
bash deploy.sh backup
ls -1 .traveler/backups
bash deploy.sh rollback 20261106-131500-0123abcd
```

Копии находятся в `.traveler/backups/<ID>`; каталог доступен только root и исключён из Git. Архивы не зашифрованы, содержат пароли и приватные ключи. Перед восстановлением проверяются SHA-256, пути, типы файлов и наличие сохранённых локальных образов. Команда восстанавливает на **этом же сервере**, в прежние тома; перенос на другой VPS пока не реализован.

Бэкапы и локальные образы автоматически не удаляются. Не запускайте `docker image prune -a`/удаление `traveler-local/*`, если нужен откат. Проверяйте свободное место. Передача внешних архивов/восстановление недоверенных бэкапов не поддерживаются.

Команды защищены общей блокировкой от одновременного выполнения. Другие инструменты, напрямую меняющие Docker или базу, этой блокировки не соблюдают.

## Резервный транспорт TCP/443

```bash
bash deploy.sh tcp-enable
bash deploy.sh tcp-export --mode tun
# только локальный SOCKS5/HTTP-прокси, без изменения маршрутов устройства:
bash deploy.sh tcp-export --mode proxy
```

Используется **Trojan поверх WebSocket и TLS**, sing-box **1.14.4**. Caddy
принимает TLS на том же TCP/443: отдельный случайный WebSocket-путь ведёт в
резервный сервис, остальные запросы — в панель wg-easy. Дополнительный внешний
порт или домен не нужен. Внутренний порт 10000 наружу не публикуется.
Основной AmneziaWG и его клиенты не меняются.

Включение выполняется с бэкапом и автоматическим откатом при неудаче.
Повторный `tcp-enable` сохраняет пароль и путь. `update`, `backup`, `rollback`
учитывают все три сервиса и секретные конфиги резервного транспорта. Чтобы
выбрать версию резервного образа при обновлении:

```bash
bash deploy.sh update --tcp-image ghcr.io/sagernet/sing-box:v1.14.4
```

Экспортированные файлы доступны только root:

- `.traveler/exports/traveler-tcp-tun.json` — полный туннель устройства (TUN,
  IPv4/IPv6-маршруты, DNS через TCP внутри резервного соединения).
- `.traveler/exports/traveler-tcp-proxy.json` — локальный прокси `127.0.0.1:2080`;
  трафик остальных приложений сам по себе не перенаправляется.

Скачайте нужный JSON через SCP/SFTP и импортируйте в совместимый клиент
sing-box 1.14.4. Это отдельный профиль, он не импортируется в AmneziaWG.
TUN требует VPN-разрешения приложения или административных прав на компьютере.
Для CLI: `sing-box run -c traveler-tcp-tun.json`; не запускайте TUN-профиль
на самом VPN-сервере — это профиль устройства.

В JSON встроен **публичный CA-сертификат Caddy**, проверка сертификата и имени
сервера включена (`insecure: false`). Устанавливать этот CA в системное
хранилище устройства не требуется. При изменении CA/IP/имени или восстановлении
старого бэкапа заново выполните `tcp-export` и импортируйте профиль. Для DNS-имени
адрес сервера разрешается в IPv4 во время экспорта, чтобы избежать DNS-петли
при установлении самого туннеля. Профиль содержит пароль: не публикуйте его.

В этой версии один общий резервный доступ; он не привязан к отдельным клиентам
панели wg-easy. Переключение между основным и резервным профилем ручное.
`doctor` дополнительно проверяет TLS с доверенным CA, WebSocket и авторизованный
Trojan CONNECT к внутренней странице входа. Это проверка туннеля на сервере,
а не гарантия прохождения фильтрации конкретного провайдера.

TCP-резерв работает без внешнего UDP, но требует доступного TLS/TCP/443.
Сети с блокировкой IP, TLS-фильтрацией, обязательным HTTP-прокси или captive
portal могут блокировать и его. На потерях пакетов он может быть медленнее
основного UDP-туннеля. Интернет-доступ по IPv6 отдельно не проверен.

Описание протокола: [Trojan](https://trojan-gfw.github.io/trojan/protocol),
[sing-box Trojan inbound](https://sing-box.sagernet.org/configuration/inbound/trojan/),
[WebSocket transport](https://sing-box.sagernet.org/configuration/shared/v2ray-transport/).

## Порты

| Порт | Назначение |
|---|---|
| 443/tcp | Панель HTTPS и резервный Trojan/WebSocket/TLS, если включён |
| 443/udp (или WG_PORT) | Основной AmneziaWG |
| 4500/udp | Запасной вход в тот же VPN |
| 53/udp на BIND_IP | Запасной вход в тот же VPN |

Панель `51821` наружу не публикуется. Для резервного UDP-порта поменяйте порт в `Endpoint` клиентского профиля. Сам номер 443 не превращает трафик в QUIC, а порт 53 не гарантирует прохождения фильтрации. При блокировке всего UDP переключитесь на экспортированный TCP-профиль.

## Разработка и проверка

`deploy.sh` — точка входа, `setup-host.sh` — зависимости только для новой установки, `traveler.py` — управление и диагностика, `tcp_fallback.py` — резервный транспорт; стандартная библиотека Python 3.10+. `docker-compose.yml` и `Caddyfile` — базовые сервисы и HTTPS.

На тестовом VPS можно выполнить реальные интеграционные проверки. Они **прерывают VPN**, создают бэкапы, обновляют образы и намеренно запускают несовместимый образ для проверки отката:

```bash
python3 tests/integration.py --allow-vpn-interruption
```

Проверяются повторная установка с конфликтующим окружением, блокировка, обнаружение остановленной панели, ручное восстановление всего тома, успешное обновление, автоматический откат после неудачного запуска, отказ скачивания. Сохранность клиентов, пользователей, паролей и SQL-хуков проверяется без вывода секретов.

После включения TCP резервный транспорт проверяется отдельно:

```bash
python3 tests/tcp_integration.py --allow-vpn-interruption
```

Тест создаёт отдельный контейнер-клиент с TUN, запрещает ему весь выход через
`eth0`, кроме TCP/443 к серверу, и проверяет DNS/HTTPS/внешний IP. Затем намеренно
ломает обновление резервного сервиса, проверяет откат и повторяет сетевой тест.
Правила firewall применяются только внутри тестового контейнера, который
удаляется в конце; firewall хоста не меняется. Только сетевой тест без
обновления: `python3 tests/tcp_integration.py --client-only`.

Внешняя проверка из другой сети (CLI sing-box и curl уже должны быть установлены):

```bash
python3 tests/external_tcp.py --binary /path/to/sing-box \
  --profile /secure/path/traveler-tcp-proxy.json --expected-ip SERVER_IP
```

Она проверяет реальный выход через сервер, отказ с неверным паролем и отказ
при несовпадении TLS-имени. На компьютере тест запускает только локальный прокси,
не меняет системные маршруты; отдельные профили и логи удаляются после проверки.
